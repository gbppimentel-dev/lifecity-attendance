LifeCity Native Android — initial implementation, v0.1.0

This is a separate React Native / Expo app in apps/mobile. It renders native
screens and uses the existing Supabase backend. It does not load the Vercel
website inside a WebView. The web v26 source and root build remain unchanged.

CURRENT VALIDATION
Nine pure logic tests and native TypeScript syntax checks pass. The website
production build is checked separately. Native dependency installation is
blocked on this PC by an untrusted Oracle Secure Web Gateway certificate.
Full native typechecking, Metro export, APK build and Android device testing
are still pending. Do not treat this initial source implementation as a
production-ready or install-tested Android release.

ALTERNATE BUILD — GITHUB ACTIONS (NO ORACLE CERTIFICATE REQUIRED ON THIS PC)
1. When ready, commit and push these additions to GitHub. Nothing was pushed
   or committed automatically. A main-branch push can also trigger your Vercel
   web deployment as usual.
2. In the GitHub repository, open Settings > Secrets and variables > Actions.
   Add repository secrets:
     MOBILE_SUPABASE_URL — the current public Supabase project URL
     MOBILE_SUPABASE_PUBLISHABLE_KEY — its public publishable key, or anon key
   Never use a service_role key or sb_secret key. The app's public configuration
   is included in its compiled binary, just as it is in the website bundle.
3. In Supabase, open Authentication > URL Configuration. ADD this Redirect URL:
     lifecity://auth/callback
   Keep all existing website redirect URLs. No SQL migration or data reset is
   needed for the native app. The existing deployed web RPCs/policies are reused.
4. In GitHub > Actions, select Android Test APK > Run workflow.
   This workflow is MANUAL ONLY. It installs the native packages, checks SDK
   compatibility, typechecks, tests, exports and builds on a Linux runner.
   Fix any failed checks before trusting the resulting APK.
5. After a successful run, download LifeCity-Android-Internal-Test from Artifacts.
   Extract the ZIP and install the APK on your Android phone. No local dev
   server is needed for this release-mode bundle. Android may ask you to allow
   installation from that download source.
6. The first run also produces android-dependency-lock. Commit the reviewed
   package-lock.json into apps/mobile so future runs use npm ci reproducibly.

The Actions workflow currently uses the Expo template's test/debug signing key
for an internal test APK. It is not a production signing setup. Choose and
back up a unique release signing key before distributing the supported release.
The provisional Android package ID is com.lifecity.attendance. Finalize it before
publishing. Without the old APK's package ID/signing key, an in-place update to
that old APK cannot be guaranteed.

Google sign-in uses the Android system's secure browser sign-in window and
returns to native screens. It does not authenticate inside an embedded WebView.
Use a native development build or the test APK, rather than Expo Go, to test
the lifecity callback scheme. No Expo account is required for the GitHub path.

LOCAL DEVELOPMENT (AFTER APPROVED NETWORK/CERTIFICATE ACCESS IS AVAILABLE)
  cd apps/mobile
  npm install
  npm run check
  npm run typecheck
  npm test
  npm run export:android
  npm run android
The last command needs Android Studio/Android SDK/JDK configured on this PC.
The public Supabase settings were copied into the ignored .env.local file.
Do not disable certificate verification or commit .env.local to fix networking.
Using a network where npm HTTPS works is another local development option.

EAS OPTION

No EAS project was created, uploaded or built during this change.

INCLUDED NATIVE WORKFLOWS
- Google sign-in, encrypted persisted sessions, role/account access checks,
  native navigation/Android Back, safe areas and reduced-motion navigation.
- Public service schedule and member connection requests.
- Member Space, upcoming services, private QR/member-ID share, profile and
  contact requests, personal attendance and feedback tickets.
- Staff dashboard; directory search, filters, star/status, private notes,
  QR verification and contact editing; churches/ministries add/rename/delete/Undo.
- Service create/edit with Manila schedule, native date picker, quarter-hour
  times, Sunday/public labels, archive/delete and Undo.
- Native camera QR/manual check-in, permissions, dimmed scan guide,
  foreground camera lifecycle, duplicate/inactive checks and feedback.
- Records filtering, dates, sorting, pagination, details, Quick CSV sharing,
  hold-to-remove and server-receipt Undo.
- Owner accounts/access and member linking, profile/link request reviews,
  activity and feedback inbox.

REMAINING PARITY AND RELEASE WORK
- Native member creation, affiliation editing, CSV import, bulk actions and
  directory exports; detailed Records CSV; native appearance palette editor;
  custom date ranges in personal history; dedicated fixed-viewport tablet kiosk.
  The existing website retains these.
- Full native typecheck/build and visual, keyboard, TalkBack, camera, auth,
  background/resume and file-sharing tests on an Android device.
- Unique production signing, finalized package ID, release versioning and
  distribution/update policy. Internet is currently required for backend work;
  there is no offline attendance write queue or native push notification service.

No live member records were changed during implementation. Test account role
boundaries and writes on a staging Supabase project before broad deployment.
